## 交付阻碍与最小复测包

1. **任务场景可达性**：P FLUENCY 夹具未得到可复习任务；缺 gloss 目标页入口未找到；跳过后仍是相同任务。先分别确认真实路由、准备场景响应和发出的任务 ID，避免在不可达场景内测判分。
2. **R FLUENCY 内容与分数解释**：修复/确认重复材料来源后，用正常学习页重复完成 2–3 次，并记录原文、词数、计时、答案、反馈及 `/score-history` 导出。产品需说明“60 分固定结果”是否符合预期；当前记录不足以推断其算法规则。
3. **结果记录完整性**：刷新恢复重测并写明实际现象；R RETRIEVE 补做错误答案；每个场景记录代码版本、时间和 CSV。仅在获得实测证据后更新通过状态。

## 与算法规格的符合性核对

核对基准为 [`docs/algorithm.md`](../docs/algorithm.md) 的学习行为和分数生命周期规则，并结合当前实现检查事件证据。算法文档明确说明它是目标设计，源码只用于核对实现，因此下表区分“规格期望”和“本次证据能否证明”。

| 现象 | 算法期望 | 核对结论 |
|---|---|---|
| ENCODE 后 Fluent/R/P 没有初始分数变化 | ENCODE 是教学/建立联系。算法明确要求曝光或教学不增加轴分；仅更新教学状态和时间锚。 | **符合期望，不是分数 BUG。** 若 ENCODE 后需要安排独立 RETRIEVE 验证，那是后续调度检查，不应期待 ENCODE 本身加分。依据：算法“教学、先验与知识迁移”；`applyTaskResult` 的 teaching 分支只更新 introduced/时间/冷却。 |
| R RETRIEVE 答对，分数 `35 → 35`，认证 `0 → 1` | RETRIEVE 可复核低于或等于已有的 checkpoint；通过不一定晋级分数。只有更高关卡通过才提高最高分。 | **符合期望，不能判为分数 BUG。** CSV 的 checkpoint 未导出，但 `35 → 35` 且认证恢复说明这是一次当前标准复核的典型结果；确切 checkpoint 仍需事件明细确认。`nextCheckpoint` 在当前验证失效时返回现有分数；服务端通过时以 `max(oldScore, checkpoint)` 写分。错误答案用例未填写，失败后的认证撤销行为未由本次手测确认。 |
| P RETRIEVE 从 `0 → 20`，无关答案不变 | 初始低分关卡为 20；通过有资格的独立答案后写入关卡分，失败保留旧分并撤销当前验证。 | **与规格相符（有限证据）。** 清单未给 CSV，能确认的只有记录中的页面分数变化；实现从 0 默认发 checkpoint 20。错误答案对应的验证/状态行为需要事件证据。 |

### 核对后的问题优先级

1. **确认为质量缺陷：R FLUENCY 生成材料重复。** 这是与算法材料条件直接冲突的用户观察；应定位书源/切片内容并增加可重复行为验收。
2. **尚未确认的潜在缺陷：R FLUENCY 分数/速度。** 补齐 checkpoint、计时、WPM、事件导出后再判断。答对 comprehension 不等于速度关卡通过。
3. **可用性/调度复测：P FLUENCY、skip、gloss、refresh。** 分别记录 EMPTY reason、任务 instance ID 与目标入口状态，区分算法结果、路由/界面问题和测试记录缺失。

ENCODE 无分数变化、R=35 的通过复核不升分，以及上滑忽略均不应按当前证据作为算法错误提交。

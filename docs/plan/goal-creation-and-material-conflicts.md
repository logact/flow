# 目标创建与材料重复关联处理计划

## 背景

目标创建时，客户端当前负责生成并在草稿中保存 `goalId`，服务端将其作为目标 ID 使用。这个做法把资源 ID 的分配交给了客户端，也容易让恢复草稿/重复提交与“创建一个新目标”混在一起。另一方面，同一材料可以属于多个目标；创建前用户需要知道所选材料已经关联到哪些目标，并明确选择是否继续。

## 决策

1. **目标 ID 由服务端生成。** 创建目标请求不再要求客户端提供 `goalId`。成功后由服务端返回新目标 ID；客户端使用响应 ID 导航或刷新数据。草稿只保存用户输入和选择，不保存待创建目标 ID。
2. **材料跨目标重复关联允许，但须先告知用户。** 客户端在创建前查询所选材料现有关联的目标。若存在关联，展示材料、目标名称及关联信息，并让用户选择返回修改或确认继续创建。
3. **服务端负责最终校验。** 预检查只用于交互提示，创建请求提交时服务端重新检查关联情况，避免检查与提交之间状态变化导致提示失效。确认意图应明确传递给创建 API；未确认且检测到关联时拒绝创建并返回可供客户端展示的冲突详情。
4. **防止重复提交由客户端和服务端共同处理。** 客户端提交期间禁用创建按钮，避免重复点击；服务端对同一创建请求提供短期防重/请求去重能力。防重键与 `goalId` 分离，不能用复用客户端提供的资源 ID 来模拟防抖。具体键的存储与有效期在实施时确定。
5. **不按材料内容自动合并目标。** 同一材料可以加入多个独立目标；同一目标中同一材料、同一分析版本的重复加入仍可按现有幂等规则处理。

## 交互流程

1. 用户填写目标信息并选择一个或多个已分析材料。
2. 客户端查询这些材料已关联的目标。
3. 无关联时直接提交创建请求；有一个或多个关联时，先显示确认提示。
4. 用户确认后，客户端携带明确的确认字段重新提交；取消则留在编辑页，不创建目标。
5. 服务端再次检查关联状态，校验确认字段及材料/分析有效性，服务端生成新的 `goalId` 并执行目标创建。
6. 成功响应返回新目标 ID 与创建结果；客户端清除草稿并刷新目标列表。

## API 与应用层调整方向

- 增加只读材料关联查询能力，支持按一组材料 ID 返回其关联目标摘要；也可扩展现有材料详情/列表 API，但响应需清楚区分无关联与加载失败。
- 创建目标 API 不接受客户端指定的 `goalId`，由服务端在执行创建时生成。
- 创建请求增加表示用户已确认重复关联的显式字段。若请求未确认且服务端发现关联，返回可识别的冲突原因和关联摘要，不产生部分目标。
- 为防止重复提交设计独立请求去重机制；重复请求返回第一次创建的结果，不能生成多个目标。机制应覆盖并发请求。
- 确认状态仅对当前所选材料和当前提交有效；材料选择发生变化后必须重新检查并重新确认。

## 数据与兼容性

- 现有目标记录及历史关联不迁移，已有 `goalId` 保持不变。
- 新建目标的客户端草稿格式移除 `goalId`。读取旧草稿时忽略旧 `goalId`，保留标题、材料、目标分数和知识点选择。
- 同一材料在多个目标之间的关联继续受现有唯一键 `(goalId, materialId)` 约束；不新增“材料全局唯一归属”限制。
- 若服务端去重依赖持久化存储，实施时需明确去重记录与目标创建的原子性和过期清理策略。

## 验收标准

- 新建目标时客户端请求不携带 `goalId`，服务端返回新生成且唯一的 ID。
- 选择的材料均未关联目标时，无额外确认步骤即可创建。
- 任一所选材料已关联目标时，创建前显示具体关联目标；取消不会创建目标，确认后可以创建新的独立目标。
- 确认后若关联状态发生变化，服务端仍按最新状态校验并要求重新确认。
- 创建按钮在请求期间不可重复触发；相同请求并发或重试不会创建多个目标。
- 相同材料可被不同目标引用；同一目标重复添加同一分析版本仍保持现有幂等行为。
- 从旧版本恢复的草稿不会复用旧目标 ID，也不会丢失其他草稿内容。

# UI 测试报告修改计划

## 目标与边界

围绕「测评 → 目标 → 材料 → 知识点 → 学习」调整原型流程和界面。

- **Domain 层冻结**：本轮不修改 `lib/domain` 的模型、函数、状态规则与不变量。
- **队列体验只改 UI**：队列中的任务答对或答错视为处理过；跳过任务仍待处理，并留在原位置。不得通过修改 domain 或 service 改变队列规则；UI 仅控制显示、滚动和导航。
- **知识点与目标的关系只在 UI 呈现层处理**：知识点在界面中按全局知识点展示，目标完成或归档不应让 UI 隐藏/删除知识点；本轮不改 domain 数据关系。
- **其他流程允许新增或调整 application service/API**：例如草稿保存、批量材料加入目标、测评后的流程分流和全局知识点查询。

## 修改项目

### P0：学习主流程与首页

1. 未完成词汇测评的学习者进入首页时，显示测评引导；不要让“今日计划为空”成为唯一提示。
2. 完成测评后按已有目标分流：
   - 没有正在学习的目标：引导创建目标。
   - 有正在学习的目标且有可学习知识点：进入该目标学习。
   - 有正在学习的目标但没有可学习知识点：引导为该目标补充材料。
3. 创建/选择流程保存后，显示明确的“开始学习”入口；点击后进入当前目标的学习。
4. 移除首页“关注 / 学习 / 复习”标签，改为可横向滑动的目标标签和“全部目标”。仅显示正在学习且未归档的目标；“全部目标”只聚合正在学习的目标，不含已完成目标。
5. 首页无目标或无任务时，按用户当前状态给出下一步引导。

### P1：目标创建、材料与选择

1. 目标创建页支持导入新材料，并可一次选择多个已分析材料。
2. 选择材料后展示合并后的候选知识点，提供全选/全不选，默认全选。
3. 选择后自动保存；从流程中途离开时保留草稿，并在目标页恢复/继续编辑。
4. 目标页提供材料管理入口。
5. 上述跨页面保存与多材料写入通过 application service/API 承载；复用现有 S05/S06 能力，必要时新增编排用例，不改 domain。

### P2：学习队列与学习卡

1. 移除答题/提取卡上多余的“完成”按钮：作答提交成功后由 UI 推进到下一张卡。
2. 跳过时滚动到队列底部；任务仍待完成且保持在队列原有顺序位置，不将跳过记为完成。
3. 按当前既有计划任务列表循环呈现，直到本队列任务均已处理；不在 UI 伪造结算结果或覆盖服务端任务状态。
4. 移除右侧浮窗入口，相关笔记/评论能力标记 TODO。
5. 移除底部中央加号。
6. 左下元信息改为 `@{来源材料名}` 并去掉“今日计划”；知识点有多个来源时显示首个材料名和省略号，点击后浮出包含全部材料的小窗。
7. 左上 Flow 标识点击展示应用介绍。

### P3：全局知识点库与入口收敛

1. 保留底部知识点库入口，移除右上角词库入口。
2. 知识点库展示全局收录知识点，支持分页，并显示分数和来源材料管理入口（标记 TODO/后续迭代，首轮可先完成列表与分页）。
3. 分数沿用当前可用的学习状态数据；实现前确认 UI 显示的分数含义和数据来源，不新增 domain 评分规则。
4. 若现有 API 无法提供全局知识点、分页和来源聚合数据，新增只读 application query service/API；不改变知识点和目标的 domain 关联。

### P4：测评覆盖范围

1. 查明当前测评最高只到词汇 4000 的原因及数据/抽样配置位置。
2. 确认产品预期测评上限后，调整测评范围与界面说明；若涉及词表数据或测评抽样逻辑，放在 application/configuration 层，domain 算法保持不变，除非另行确认。

## 建议实施顺序

1. 先补齐首页状态分流和目标标签，让主路径可走通。
2. 实现目标创建的多材料选择、知识点选择、自动保存与草稿恢复。
3. 调整学习卡 UI 和队列导航，严格保持 domain/service 队列行为不变。
4. 收敛导航入口并实现全局知识点库查询展示。
5. 最后处理测评范围和应用介绍等独立项。

## 验收要点

- Domain 目录无修改；不改变现有 service 的队列状态、顺序或完成判定。
- 跳过后任务仍待处理并留在既定队列位置；答题成功后 UI 自动前进。
- 完成测评后的三种目标状态分流正确。
- 创建目标支持多个材料和知识点全选/全不选，离开后草稿可恢复。
- 目标标签只包含正在学习且未归档目标，“全部目标”不纳入已完成目标。
- 全局知识点库不因目标归档/完成而隐藏知识点；多个材料来源可展开查看。
- 右上角词库、关注/复习标签、右下浮窗和底部加号均按计划移除。

## 暂定项

- “答错算处理过”意味着本轮 UI 不会将答错任务留在当前待做队列里重复；是否由服务端后续复习计划重新安排，沿用现有规则。
- 测评最高范围的目标上限待产品确认；计划阶段先定位限制来源，不擅自扩大词表范围。
- 知识点列表“分数”的显示名称和具体字段需要在实现前对应到现有数据，避免把掌握度、目标分或测评分混为一谈。

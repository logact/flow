# 新算法场景设计（已确认）

依据 [algorithm.md](./algorithm.md) 当前版本。场景设计已获用户确认；本文定义测试输入和预期，**没有声明这些场景已经实现或通过**。`D0` 为用户本地引入日；`due_R/P`、`level_R/P` 分别为两轴排期和下一次待做间隔。除特别说明，目标 R/P 均为 80，材料和判分有效，时钟与全局 tick 可控。

## 报告格式

每条转移一行：`场景 ID｜当前分数(状态) → 任务/作答 → 分数变化 → 新分数(状态)｜due_R/P、level_R/P、容量变化`。复习失败和不变分也要写明计算依据、真实任务实例与事件；无效作答写 `不结算`，不能伪造一笔 0 分变化。所有自动化先测纯状态函数，再用临时库测原子回写与正式调度；正式 UI/材料另按 V 节点验收。

## B. FLUENCY 分数与有效性

| ID | 初态与动作 | 必须看到的结果 |
|---|---|---|
| B01 | R=80；100 词，阅读 30 秒，两题正确 | 200 wpm，`60+(200−150)/3.75=73.333…`，R 80→73.333…；目标 80 未达，不产生达标证据 |
| B02 | R=60；100 词，阅读 40/26.666…/20 秒，两题正确 | 150/225/300 wpm → 60/80/100；按未舍入值比较目标，不能保留历史最高分 |
| B03 | R=80；目标词题错、整体题任意 | R 80→40；该轴若在复习，则退级、撤出复习并当天补练 |
| B04 | R=80；目标词题对、整体题错 | R 80→80，有效不变分；若在复习则本轮未通过、退级重排，不算无效 |
| B05 | R=80；两题正确但 149.9 wpm | R 80→40；重新按 free 补练，不能以分数上限掩盖速度失败 |
| B06 | R 阅读后回看两次 | `reading_seconds=首读+两次回看`；答题时间不计入；短文不是 100 词或目标出现不足 5 次不可签发 |
| B07 | P=80；30 个有效英文词、40 秒、两项通过 | 45 wpm，`60+(45−25)×40/35=82.857…`，P 80→82.857… |
| B08 | P=80；两项通过，24.9/25/42.5/60 wpm | 依次设 40/60/80/100；目标 80 时只有后两者可给达标证据 |
| B09 | P=80；目标词没用/用错，整体任意 | P 80→40；若在复习则只影响 P 的排期 |
| B10 | P=80；目标词正确，整体未通过 | P 80→80，有效不变分；复习不得升级 |
| B11 | P 少于 30 个有效英文词 | 提示继续编辑，不冻结完整答案、不计算速度、不结算 |
| B12 | P 从开始到提交恰好 5 秒；或 R/P 中断、计时无效 | P `≤5 秒` 无效；所有这些情况 F/due/level/tick/容量均不变，重开不得拼接计时 |
| B13 | AI 不确定、服务失败或材料错误 | 保留冻结作答待重试；不误判失败、不改分或排期；重复判分最多完成一次结算 |

## C. R/P 独立复习与毕业

| ID | 初态与动作 | 必须看到的结果 |
|---|---|---|
| C01 | D0 R 达标，P 仍 60；D1 R 到期 | `due_R=D1, level_R=1`；P 仍学习 `due_P=D0` 且已逾期；R 复习优先，P 不阻止 R 排期 |
| C02 | D1 P 首次达标，R 已有确定排期 | P 从 D1 排自己的第 1/4/11/41 天；R 日期不改，条件预约逐轴落日 |
| C03 | R 连续通过自己的四次复习 | R 在相对达标日第 1→4→11→41 天各做一题；level 1→3→7→30→轴毕业，`due_R=∞` |
| C04 | R 已毕业而 P 尚未毕业 | R 不再派题；P 可继续学习/复习；词 `graduated=false` |
| C05 | P 也通过自己的 30 天复习 | `graduated_P=true, due_P=∞`，词 `graduated=true`；不再生成任一轴任务 |
| C06 | 同一天 R/P 都到期 | 各自有独立复习实例和容量占用；一题完成后另一题仍受词级冷却；任一轴结果不改另一轴 `due/level` |
| C07 | R 在 level=1/3/7/30 的复习中目标题错 | R 分数按规则降低；R 下次级别分别 1/1/3/7，`due_R=失败当天` 学习补练；P 不变 |
| C08 | R 在四级复习中整体题错但目标题对，分数不变 | 有效未通过，R 下次级别分别 1/1/3/7；重排日期的计算锚点待确认；P 不变 |
| C09 | R 降分后 free 补练至 60，再有效 FLUENCY 达标 | R 重新获得证据，从退回的间隔排自己的下一次复习；P 原排期不变 |
| C10 | 一轴复习作答无效/不确定、另一轴已通过 | 无效轴原 `due/level` 不变，可重试；已通过轴的升级和排期不撤销 |
| C11 | 到期未练，跨本地日后完成 | 原 `due_a` 保持逾期直到有效结算；成功后的下一间隔计算锚点待确认，不悄悄挪动原到期日 |
| C12 | 用户改变 R 或 P 的目标为 60/100 | 分数不变；分别重审达标证据、轴毕业资格和未执行预约，记录调整原因；另一轴目标不被覆盖 |

## D. 冷却、派题和容量

| ID | 初态与动作 | 必须看到的结果 |
|---|---|---|
| D01 | 刚完成同词 R，马上想做 P | P 与 R 共用锚，先等待；7 个**其他**有效任务或 20 分钟任一满足才可再派 |
| D02 | 先后完成 6/7 个其他有效任务，时间未满 20 分钟 | 第 6 个仍等，第 7 个可派；skip/exit/invalid 不推进 tick |
| D03 | 无其他任务，时间经过 19:59/20:00 | 前者等，后者可派；等待响应给出最早可用时间，不显示“今日完成” |
| D04 | 同时有逾期复习轴、逾期学习轴、新词 | 先选复习轴，再学习轴，最后新词；组内最早 `due_a`、词 ID、R 再 P |
| D05 | 高优先级轴冷却未就绪，次候选已就绪 | 先派可练的次候选；高优先级轴就绪后重新比较 |
| D06 | 今日容量 9，只有一个 0 分新词、材料齐且时间充足 | 最多准入 1 词；当天预留连接 1+双轴提取 6+双轴 FLUENCY 2；还须能遵守冷却 |
| D07 | 今日容量 8，或虽有 9 格但剩余时间不足 | 不准入需 9 格的 0 分新词；返回具体容量/时间原因，不宣称今天流程保证完成 |
| D08 | R/P 同日达标及错日达标 | 未来容量按各轴第 1/4/11/41 天分别预留 1 题；确定排期与条件预约分列，落在同一天时合计 2 题 |
| D09 | 实际失败、目标变化或复习退级 | 撤销目标轴不再成立的条件预约，重算各日 `remaining`；保留另一轴已确定排期；不静默顺延逾期 |
| D10 | 未来任一天已超容量 | 停止准入新词，显示缺口；已有到期轴仍保持原 `due_a`；逐日剩余可为负以暴露短缺 |
| D11 | 今天没有可派旧轴且没有新词容量 | 区分 `today_complete`、容量不足、冷却等待、材料失败、空范围；仅确实完成时说“今天已练习完成” |
| D12 | 本地午夜、时区或夏令时切换 | 按用户本地日历计算 1/3/7/30 天；同一实例跨日重试不重复派题或占容量 |
| D13 | 当天剩余 3/5/7/9 格，各有对应初分的新词 | 在材料与冷却时间都充足时，分别只准入最短路径需 3/5/7/9 题的词；少一格即拒绝，不能对所有词固定扣 9 格 |
| D14 | R 初分 60、P 初分 40，R 首题 FLUENCY 通过，P 仍学习 | R 从实际通过日排自己的 1/4/11/41 天预约；P 仍占当天 free+FLUENCY 的估计容量，不能因 R 初分 60 就提前设复习证据 |

## E. 材料、实例与恢复

| ID | 初态与动作 | 必须看到的结果 |
|---|---|---|
| E01 | 当前轴 FLUENCY 材料不可用，但 RETRIEVE 材料可用 | 不降档；有限生成与校验后仍失败则比较其他候选，记录材料原因 |
| E02 | 目标释义缺失或用户修改 gloss | 未确认释义不作为判分依据；旧版本未提交实例按契约失效；已冻结作答按原答案键处理 |
| E03 | 同实例重复提交或并发不同答案 | 只接受首次完整作答；相同请求重放原结果，冲突返回错误；F/due/tick/容量只结算一次 |
| E04 | 显式 skip、exit、刷新、中断 | 记录互斥终态；skip/exit 不改分、排期、冷却或 tick；FLUENCY 中断重开新计时 |
| E05 | 判分服务失败后恢复 | 保留原答案、计时、材料版本；有限重试后才原子结算；错误体不泄露答案键 |
| E06 | 历史与容量对账 | 每行展示 `旧分→新分`、计算依据、目标轴 `旧due→新due`、级别/毕业、当日完成与预约变化；事件能重放相同结果 |
| E07 | 正式导入 `V=4000, rank=1000` 后请求下一题 | API/DB 保存 `V`、rank 来源、R60/P40 和估计来源；正式调度直接签发 R FLUENCY 或 P free，不产生连接实例；重复请求不重复准入或占容量 |

## 需要先讨论的边界

1. **逾期成功后的下一次日期**：本稿按“实际结算日 + 下一级间隔”设计；权威规范目前没有用一句话固定该锚点。实际结算日 + 下一级间隔”
2. **目标改动与已毕业轴**：若用户提高目标，旧轴毕业是否撤销，以及原 FLUENCY 通过证据如何重新评估，需要明确。旧轴毕业需要撤销 只是把dueat 设为今天然后fluency 保留原样
3. **新词首日任务的可完成性**：按估计初分分别需要最少 3/5/7/9 题；只有一个新词时仍需靠 20 分钟冷却反复等待。“当天剩余时间足够”的可计算口径尚未冻结；容量够但冷却未到时保持等待。
4. **未来容量展示**：规范要求内部算至第 41 天；可讨论 UI 只显示未来 30 天，但新词准入仍需覆盖第 41 天。UI 也显示41天
5. **按轴的条件预约**：未达标轴的预计达标日可能漂移，需要确认容量估算是保守上界、理想路径，还是显示区间。理想路径 按照都在due_at 那一天复习到了，并且没有答错

场景设计已确认。下一步按本稿拆成 Jest 状态转移用例、临时库/调度集成用例和 V01–V08 的正式入口验收；实现及运行前不计入当前通过率。

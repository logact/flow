# Loop8 实施计划

## 目标

完善材料分析到目标创建的知识点流程：用户在材料详情显式解析待处理候选，sense 解析成功后尽量补充对应中文释义；解析后仍缺少释义的知识点可在材料知识点列表中批量补充；目标创建只允许选择已经解析并保存的正式知识点。

## 决策依据

- [Sense 解析时查询中文释义决策](decision/chinese-meaning-during-sense-resolution.decision.md)：中文释义对应最终选定的 sense；翻译失败不应使 sense 解析失败。
- [材料知识点列表批量补充中文释义决策](decision/material-knowledge-list-batch-chinese-meaning.decision.md)：材料列表提供单项/批量补充缺失释义的入口，按知识点独立处理并支持重试。
- [目标创建仅选择已解析知识点决策](decision/goal-selection-resolved-knowledge-only.decision.md)：目标创建只选择已保存的正式知识点，不在目标提交中解析候选或调用翻译服务。

## 流程与数据边界

1. 材料导入和分析生成正式知识点及待解析候选。
2. 用户在材料详情选择待解析候选并显式触发 sense 解析。
3. 每个候选独立确定 sense 并保存为正式知识点；随后以该 sense 补充中文释义。翻译失败不回滚已保存的 sense/知识点，只留下释义待补状态。
4. 对已解析但缺少中文释义的知识点，用户可在同一材料知识点列表逐项选择或全选缺失项，执行批量补充并重试失败项。
5. 用户在目标创建页只选择已解析并保存的正式知识点；目标提交仅保存目标及选择关系。

**状态边界**

- 候选的 sense 解析状态与知识点中文释义补全状态分开管理。翻译失败不能把候选重新置为待解析或使已完成解析显示失败。
- 候选解析阶段的释义查询和列表批量补充共享同一个知识点 sense 中文释义字段及补全状态。已有有效释义不覆盖；批量入口只针对已确定的 sense，不再次调用 sense 消歧。
- 每个候选/知识点单独保存成功、失败和可重试状态；部分成功不能回滚其他项目。
- 沿用现有学习者鉴权、材料归属、分析版本校验及候选解析持久化幂等规则。新释义操作也必须验证当前学习者对材料和知识点的访问权限，并防止并发重复翻译。

## 场景 1：解析候选并独立补充中文释义

### Domain

- 明确候选 sense 解析状态与知识点中文释义补全状态的独立模型和转换规则。
- 中文释义字段继续归属最终确定的 sense/知识点；兼容已有数据和本地确定性解析结果。
- 定义翻译待补、处理中、完成、失败状态及失败信息的持久化方式。有效的既有中文释义不能被自动覆盖。

### Service

- 保留材料详情显式触发候选解析、逐候选持久化和解析幂等行为。
- sense 选择成功后先持久化正式知识点及解析成功状态，再尝试查询中文释义；翻译失败只记录为释义待补/失败，不回滚知识点，也不重做 sense 消歧。
- 提供释义独立重试能力，重试仅调用中文翻译服务，不调用 sense 解析服务。
- 翻译操作按知识点/sense 认领并去重；检查分析版本和学习者归属，已完成释义直接复用。

### UI

- 材料详情候选解析仍由用户显式启动，并逐项呈现解析状态。
- 解析完成后展示已保存知识点及中文释义补全状态；翻译失败与 sense 解析失败应有不同反馈和恢复入口。

### 验收

- sense 解析成功且翻译成功时，sense 与对应中文释义均持久化。
- 翻译失败时知识点仍可使用，解析状态保持成功，释义可独立重试且不重复调用 sense provider。
- 已有释义不被重复请求或覆盖；并发、重复提交和重启恢复遵守持久化状态及幂等约定。
- 对失效分析版本、未授权材料及不属于当前学习者的资源拒绝处理。

## 场景 2：材料知识点列表批量补充缺失中文释义

### Domain

- 复用场景 1 定义的知识点中文释义及补全状态，不为批量入口创建第二套释义数据。
- 明确“缺失中文释义”的筛选条件；空值或明确失败/待补状态可纳入，已有有效释义默认排除。

### Service

- 提供单项及批量中文释义补充能力，逐知识点执行并持久化结果；一个项目失败不影响其他项目。
- 批量请求校验每个知识点属于当前材料、当前学习者且已有确定的 sense。越权或无效 ID 不得访问或修改其他资源。
- 操作遵守重复提交保护；已完成项目返回现有释义，不重复请求翻译服务。
- 失败项可单独重试或再次批量提交；此操作不得触发材料分析或 sense 消歧。

### UI

- 在材料详情“分析知识点”列表展示中文释义及补全状态。
- 支持逐项选择、全选缺少中文释义的知识点、调整选择后批量提交。
- 展示逐项处理中、成功和失败结果；支持失败项单独重试，并保留已成功结果。

### 验收

- 用户可全选缺失项、调整选择并提交；已有释义默认不被选中、请求或覆盖。
- 批量部分成功时成功结果立即保留，失败项状态清晰且可重试。
- 单项和批量补充均只针对现有 sense，不触发 sense 消歧或重新分析。
- 刷新、重复提交及并发请求不会重复翻译已完成项目；鉴权和材料归属逐项有效。

## 场景 3：目标创建只选择已解析知识点

### Domain

- 目标知识点选择仅接受已保存、可学习的正式知识点，不将候选实体作为目标选择项。
- 保留知识点来源材料和当前学习者归属校验。

### Service

- 目标创建/编辑查询只返回已解析并保存的知识点。
- 创建和更新接口拒绝待处理候选 ID、未知 ID 及其他学习者资源 ID。
- 目标相关请求只保存目标与正式知识点的选择关系，不调用 sense 解析或中文翻译 provider。

### UI

- 目标创建页仅展示已解析的正式知识点。
- 待解析候选需先回到材料详情处理；解析成功后再返回目标创建选择。
- 其他知识点可继续正常选择，即使某些材料候选仍在处理中或解析失败。

### 验收

- 目标创建页不展示待解析候选，已解析知识点可正常选择并创建目标。
- API 拒绝候选 ID 和越权/无效知识点 ID；请求不会触发 AI sense 解析或释义翻译。
- 页面加载及提交均不触发材料候选解析；现有目标及任务行为保持可用。

## 实施顺序与依赖

1. 先落实释义字段和独立状态边界，以及解析成功后“先保存 sense、再补释义”的服务行为。
2. 在同一数据与服务能力上增加材料知识点列表单项/批量补充和逐项反馈，避免形成第二套释义状态。
3. 将目标创建查询、校验和 UI 收敛到已解析知识点，并移除目标提交路径中候选解析/翻译行为。
4. 对三条路径进行端到端核对：候选解析、释义补充、目标选择分别验证状态、权限、幂等和失败恢复边界。

## 范围外

- 不改变材料主体分析、候选 sense 解析的用户显式触发方式。
- 不把发音查询并入 sense 或中文释义流程；发音继续沿用现有独立补全机制。
- 不改变 Loop5 已有的候选持久化、跨进程认领、分析版本及多学习者鉴权规则。

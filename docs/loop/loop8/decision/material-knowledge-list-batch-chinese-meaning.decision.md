# 材料知识点列表批量补充中文释义决策

## 决策

- 在材料详情的“分析知识点”列表内提供中文释义查询入口。每个知识点可单独选择，并提供“全选缺少中文释义的知识点”操作，支持批量查询。
- 批量查询只处理当前知识点已确定的 sense 的中文释义，不重新执行材料分析或 AI sense 消歧；中文释义必须基于该 sense 的英文释义生成。
- 已有中文释义的知识点默认排除，避免覆盖有效内容或重复消耗查询。用户可取消全选结果中的单项，再提交剩余选择。
- 列表展示中文释义及待查询、查询中、失败状态。批量部分成功时保留并展示成功项，明确标出失败项；失败项可以单独重试或再次加入批量查询。
- 此列表操作是对缺失中文释义的补充入口，与候选解析期间查询中文释义的决策分开管理；两种路径共享同一份 sense 中文释义数据，并遵守不覆盖已有有效释义的规则。

## 实施边界

- 查询和保存按知识点/sense 独立处理，单项失败不得回滚其他知识点的成功结果。
- 状态和重试应针对中文释义补全本身，不能把已完成的材料分析或 sense 解析重新标记为处理中/失败。
- 逐项校验当前学习者对材料及知识点的访问权限；批量请求中的越权或无效 ID 不得访问或修改其他学习者的数据。
- 请求应具备重复提交保护；已完成项在重复请求中直接返回现有结果，不重复调用翻译服务。

## 当前问题

- 当前材料详情的知识点列表只显示英文释义，未显示中文释义，也没有单项选择、全选或批量补充入口。
- 已有 `/api/knowledge/[id]/meaning` 单项补充能力，但材料列表没有直达该操作的交互；逐个离开材料上下文不利于批量补齐。

## 验收方向

- 用户可在材料知识点列表全选缺少中文释义的条目，查看并调整选择后一次提交。
- 查询成功的中文释义显示在对应条目；已有释义的条目默认不被请求或覆盖。
- 查询中及失败状态清晰可见；单项重试和部分成功后重试不会重新执行 sense 消歧，也不影响其他成功项。
- 重复提交、并发操作及刷新后不会重复查询已完成项，状态与结果保持一致。

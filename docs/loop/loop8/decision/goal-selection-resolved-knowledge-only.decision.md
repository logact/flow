# 目标创建仅选择已解析知识点决策

## 决策变更

- 目标创建恢复为仅从已解析并保存的知识点中选择；材料中的待解析候选不得暂存为目标选择，也不得在目标提交时触发 AI sense 消歧或释义查询。
- 用户需要先在材料流程中完成候选解析，使候选成为正式知识点，再返回目标创建选择该知识点。
- 目标创建继续校验知识点及其来源材料归属和当前学习者权限；请求中提交的 ID 必须对应已存在、可学习的知识点。
- 候选解析失败或仍在处理中时不影响目标创建页中其他已解析知识点的选择，但这些候选本身不可选。目标创建不负责重试或恢复材料候选解析。

## 被替代的既有决策

- 本决策替代 Loop5 决策 `docs/loop/loop5/materilaAnalyzeOptimize.decision.md` 中“目标创建/编辑时可选择未解析候选，并在目标提交时仅解析所选候选”的交互与服务行为。
- 本决策也替代 Loop5 计划 `docs/loop/loop5/loop5.plan.md` 场景三中“目标提交时解析所选候选”的实施描述。
- Loop5 其余候选能力仍然有效：材料详情可显式批量解析待处理候选、逐项重试，并持久化解析结果；解析完成后的正式知识点仍可进入目标。

## 流程

1. 材料导入和本地分析生成已确定知识点及待解析候选。
2. 用户在材料详情显式解析候选；成功后候选成为正式知识点。
3. 用户在目标创建页只浏览和选择已解析知识点。
4. 目标提交只创建/更新目标及其知识点选择，不调用候选 sense 解析或中文释义翻译服务。

## 验收方向

- 目标创建页不展示可选的待解析候选；仅展示已解析知识点。
- 目标创建 API 对待解析候选 ID、未知 ID、其他学习者资源 ID 均拒绝，且不触发 AI 或翻译 provider。
- 目标创建页面加载和提交不会触发材料候选解析；候选需先在材料详情解析成功后才可供选择。
- 已解析知识点的既有选择、创建目标和任务行为保持可用。

## scenarios

### scenario1：发音反馈与历史中文释义补全

#### include decision

- `pronunciation-playback-feedback.decision.md`：区分无音频、播放中和播放失败，保留缓存地址及来源信息。
- `chinese-meaning-backfill.decision.md`：按当前 sense 补全历史中文释义，支持失败后重试且不跨 sense 借用释义。

#### description

学习任务能够如实表达缓存发音是否可用及播放失败状态。已有中文释义缺失的知识点可以针对当前 sense 补全；补全失败时保留原数据并允许再次尝试，不影响任务学习。

#### impl plan

**domain**

- 保持释义归属于 sense、发音元数据归属于词条的既有数据边界；确认补全结果可区分未尝试、失败和无结果。
- 不改变发音来源及缓存音频的既有约束。

**service**

- 为历史缺失释义提供针对当前 sense 的补全/重试流程；重复请求安全，失败不覆盖已保存释义。
- 播放流程只消费缓存音频 URL，不在播放时请求词典；补全音频或释义的外部调用失败不得阻塞学习。

**UI**

- 发音控件呈现无音频、播放中、播放失败及可重试状态，并保留来源链接。
- 释义缺失时呈现可识别状态和按需补全入口；补全中、成功、失败及无结果均有明确反馈。

#### 实施记录

- 已完成：学习任务发音控件显式显示无音频状态；已有缓存地址的播放仍在播放失败时给出反馈并支持再次点击，来源链接保持显示。
- 已完成：新增按知识点 ID 的中文释义补全接口，只补当前 sense 的空值；结果写回知识点及材料分析中的关联副本。翻译无结果或调用失败不会覆盖已有数据，缓存只保留成功译文，失败后允许重试。
- 已完成：学习任务提供补全入口，并显示处理中、暂不可用和失败可重试反馈。
- 后续修正：释义写回只更新已完成分析中的关联知识点；pending/failed 分析记录保持原样（与判型一致）。
- 验证：未运行测试（本次请求未要求运行测试）；通过变更审阅确认播放仍只用缓存音频 URL，接口更新数据时基于最新仓库快照。
- 提交：`71c7b22 feat: backfill missing sense meanings`。

### scenario2：材料分析启动与状态呈现

#### include decision

- `material-detail-manual-analysis.decision.md`：进入详情只读取状态，分析由用户显式启动。
- `material-analysis-status-copy.decision.md`：列表与详情使用一致状态文案，并单独说明超时可恢复。

#### description

用户进入或刷新材料详情不会启动分析。未开始时用户可显式开始；处理中、完成、失败及超时可恢复状态在列表和详情中语义一致，恢复操作不会产生重复并发分析。

#### impl plan

**domain**

- 不改变分析状态枚举或状态转换规则。

**service**

- 保持详情 GET 只读、分析 POST 显式启动；沿用现有并发去重、pending 超时恢复和原材料复用规则。
- 确认列表与详情消费同一状态映射，避免各自解释 `pending`。

**UI**

- 统一状态标签：`pending` 为“分析中”，`analyzed` 为“分析完成”，`failed` 为“分析失败”；无记录时列表为“未分析”、详情为“未开始”。
- 超时仍保留“分析中”主状态，同时显示超时说明和恢复/重试入口。
- 只有未开始、失败或超时状态显示相应显式操作；处理中页面说明自动更新，不暗示进入页面会触发分析。

#### 实施记录

- 已完成：抽取材料分析状态文案函数，导入列表、材料库列表和材料详情对 pending/analyzed/failed 使用相同主状态；无记录分别显示“未分析”和“未开始”。
- 已完成：列表、材料库和详情统一按 2 分钟识别超时；列表提供恢复重试，材料库给出详情恢复提示，详情保留“分析中”主状态并说明超时可恢复。
- 已确认：材料详情 GET 仍仅读状态；启动和恢复继续由用户点击后调用现有 POST，不改变既有并发去重、超时恢复及材料复用逻辑。
- 验证：未运行测试（本次请求未要求运行测试）；通过调用路径审阅确认打开/刷新详情不会触发分析请求。
- 提交：`edaae8d feat: unify material analysis status`。

### scenario3：知识库筛选与列表视觉层级

#### include decision

- `knowledge-source-filter.decision.md`：保留来源材料多选语义，改善窄屏筛选器可见性和操作性。
- `knowledge-typography.decision.md`：统一知识点列表标题、释义、辅助信息、来源与操作的字体层级。

#### description

全局知识库在保留现有多来源筛选行为的基础上，筛选选择和清除操作易于发现；列表在窄屏下仍可读，长词条和材料名称可自然换行，整体遵循应用现有暗色主题和字体。

#### impl plan

**domain**

- 不涉及。

**service**

- 沿用现有多值 `sourceId` 查询及“匹配任一所选来源”的筛选语义，不新增重复筛选逻辑。

**UI**

- 调整来源筛选器宽度、排布、标签间距、选中态和清除入口；窄屏下避免挤压搜索、排序和列表区域。
- 建立一致的标题、释义、熟练度/词族、来源链接和操作入口层级；沿用现有字体与主题，检查中英文混排和长文本换行。

#### 实施记录

- 已完成：窄屏将搜索与排序控件纵向排列；来源选项可滚动；知识点标题、释义、辅助信息、来源链接和详情入口采用一致层级，并允许长文本换行。
- 验证：未运行测试（本次请求未要求运行测试）；通过变更审阅确认 API 筛选及排序行为未变更。

### scenario4：词汇测评自适应抽样与提前结算

#### include decision

- `vocabulary-assessment-adaptive-sampling.decision.md`：按词频段递进；每段 6 题起步，边界时追加 4 题、必要时再追加 2 题，每段最多 12 题；取消固定总题数上限；支持任意批次后主动结算。

#### description

测评按低频到高频逐段抽样。每段首批结果按既定规则停止、确认或进入下一批；最高频段可以测满本段上限。用户随时可以提前结束，已答结果参与结算，结果呈现样本不确定性。抽样按词族去重、层内不放回，并在相同输入及随机种子下可复现。

#### impl plan

**domain**

- 将批次大小、每段最多 12 题、首批 0–2/3–5/6 的分流规则以及频段递进/停止决策集中定义为领域策略。
- 复用现有词频估计及 Wilson 区间能力。为 10 题和 12 题节点补充累计判断规则，并明确如何据此更新已测频段估计及能力上界。
- 10 题按 Wilson 区间对 0.5 判定线分流：9–10 题进入下一段，0–1 题停止向上探索，2–8 题追加 2 题；12 题时 10–12 题进入下一段、0–2 题停止、3–9 题作为未确认边界停止向上探索，保留不确定性提示。不得将小样本比例直接标为确定掌握率。
- 保持词族去重、层内不放回及给定输入可复现；抽样会话追加批次不得与已发题目重复。

**service**

- 将一次性生成固定题量改为依据 domain 下一步决策逐批生成、记录并继续；持久化测评会话、批次、题目和答题，使刷新或重试不丢失已答结果。
- 提供主动结束并结算路径；提交和结算保持幂等，不能重复计入答题或重复完成测评。
- 自动停止或提前结束时，基于已完成题目调用现有估计逻辑，并保留样本量及区间等置信度证据。

**UI**

- 移除固定 100 题且不可退出的流程；展示当前频段、该段已答题数、下一步状态及实时总体进度。
- 提供随时主动结束入口；提前结算时展示估计结果及其不确定性，不暗示未测频段已确认。
- 达到最高频段时允许完成该段最多 12 题后结算；能力上界说明与当前抽样覆盖范围一致。

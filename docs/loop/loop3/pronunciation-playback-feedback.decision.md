# Loop3 发音播放失败反馈决策

## 决策

- 对应人工评审第 1 条：发音控件需要让用户明确知道音频是否可用、播放是否成功。存在缓存音频地址时允许用户主动播放；没有音频地址时显示不可用状态；播放失败时保留明确反馈，不能只留下看似可用的扬声器图标。
- 播放继续使用知识点缓存的词典音频 URL，不在每次点击时重新查询词典。显示已有的发音来源及来源链接，便于判断音频来源。
- 调查截图时无法判定本次失败是地址失效、浏览器策略还是设备输出问题；实施时应分别检查音频地址缺失和 `audio.play()` reject 的界面反馈，不把 UI 显示按钮等同于音频可播放。

## 实施范围

- **Domain**：不改变发音元数据和词典来源决策。
- **Service**：不在播放时发起新的词典请求；保留已缓存音频地址。
- **UI**：区分无音频、播放中和播放失败；失败状态应可见且可再次尝试。

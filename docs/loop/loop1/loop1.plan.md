# loop1 执行计划

## 计划范围

本计划聚合 loop1 中现有的四份 decision，并纳入 `human-verify.record.md` 第 16–22 条，作为后续实现的执行顺序与验收依据：

1. [目标创建与材料重复关联处理](goal-creation-and-material-conflicts.decision.md)
2. [目标展示页面学习进度优化](goal-progress-display.decision.md)
3. [ENCODE 页面中文释义归属](encode-sense-chinese-meaning.decision.md)
4. [首页手动刷新计划入口调整](home-plan-refresh.decision.md)

第 16–22 条目前以需求记录形式纳入计划；执行时如发现数据模型、交互行为或验收口径需要产品决策，应先补充对应 decision，再继续实现。

## 执行原则

- 按下列阶段顺序实现；每个阶段以对应 decision 的验收标准为完成条件。
- 保持现有目标、材料、知识点和学习记录数据兼容；如实现调查发现需要改变决策，先更新 decision，再继续实现。
- 改动按领域拆分，避免把目标创建、学习进度、释义数据和首页计划交互耦合成一次大改。
- UI 状态需要覆盖加载中、成功、空数据和失败等适用场景；具体细节遵循对应 decision。

## 阶段一：目标创建与材料关联校验

**依据：** `goal-creation-and-material-conflicts.decision.md`

1. 梳理目标创建页面、创建 API、应用用例及材料与目标的持久化关联。
2. 将新目标 ID 的生成职责放到服务端；创建草稿不再依赖待创建的目标 ID，并兼容恢复旧草稿。
3. 增加所选材料关联目标的预检查与冲突详情反馈；提交时由服务端重新校验，并要求显式确认重复关联。
4. 在客户端提交期间阻止重复操作，并为服务端创建请求提供与资源 ID 分离的并发防重机制。
5. 保持材料可以关联多个不同目标，同一目标内相同分析版本的幂等行为按现有规则处理。

**完成条件：** 满足该 decision 的全部验收标准，尤其是服务端生成 ID、重复关联确认、提交时二次校验、并发请求不重复创建，以及旧草稿兼容。

## 阶段二：ENCODE 中文释义数据链路

**依据：** `encode-sense-chinese-meaning.decision.md`

1. 调查知识点/sense 创建、导入、补全和持久化链路，确定中文释义字段归属及生成入口。
2. 为已有知识点明确缺失释义的处理方式，确保不会借用同词其他 sense 的释义。
3. 让 ENCODE 任务生成和页面展示通过当前知识点/sense 读取已保存的中文释义；如需保证历史内容稳定，使用任务快照引用该数据。
4. 保持英文释义、例句及其中文翻译等任务内容不在本决策范围内。

**完成条件：** 同一 sense 的多个 ENCODE 任务使用一致释义；多义词不同 sense 可展示各自释义；缺失释义有明确状态且不会串用。

## 阶段三：目标详情页进度摘要

**依据：** `goal-progress-display.decision.md`

1. 在目标详情数据链路中计算或返回已选知识点的汇总状态，优先复用目标详情 API，统一统计口径。
2. 仅将选择学习的知识点纳入统计；R 与 P 均毕业才计为完成，并区分未初始化、进行中和已完成。
3. 在目标详情页增加完成率、数量、R/P 当前平均值与目标值对照，以及按空状态和完成状态变化的下一步提示。
4. 处理无数据和错误状态，不以 0 替代缺失数据；确保窄屏可读，进度信息有可访问文本说明。

**完成条件：** 页面摘要与知识点列表状态一致，覆盖空集合、未初始化、部分毕业和全部完成等情况，且不将目标掌握进度描述为每日任务完成率。

## 阶段四：首页计划加载与重试入口

**依据：** `home-plan-refresh.decision.md`

1. 核对首页首次进入与任务结算后的计划更新路径。
2. 移除常驻的“刷新计划”入口，保留页面加载及任务结算触发的自动更新。
3. 补充明确的加载状态；加载失败时提供“重试加载”操作，并确保文案不承诺改变或重排计划。

**完成条件：** 首页自动加载计划、任务提交后更新计划；失败可重试且请求中有反馈；不再呈现常驻刷新入口。

## 阶段五：材料导入与分析解耦

**依据：** `human-verify.record.md` 第 16 条

1. 调整材料新增流程，使保存材料与触发分析成为两个明确操作。
2. 添加成功后展示材料记录及可用状态；由用户显式触发分析，并反馈排队、处理中、完成或失败状态。
3. 分析失败后允许单独重试分析，不重复创建材料；避免同一材料被重复并行分析。
4. 确认目标创建和其他既有流程只消费已分析完成且有效的材料/知识点。

**完成条件：** 添加材料不会自动启动分析；用户可单独启动和重试分析；分析状态可见，重复操作不会产生重复材料或并行重复任务。

## 阶段六：独立材料管理页与详情

**依据：** `human-verify.record.md` 第 17 条

1. 新增材料管理页，并在目标管理页提供清晰入口。
2. 材料列表支持查看材料状态和基础信息；列表呈现与导入/分析状态保持一致。
3. 材料详情展示该材料分析得到的知识点，并提供筛选与排序。
4. 处理无分析结果、分析中、分析失败和空知识点等状态；详情数据按材料来源限定，避免展示其他材料的知识点。

**完成条件：** 可从目标管理页进入材料管理页，打开材料详情查看对应分析结果，并使用筛选和排序找到知识点。

## 阶段七：目标管理页区块展示

**依据：** `human-verify.record.md` 第 18 条

1. 将目标列表整理为独立区块/卡片，明确每个区块对应一个目标。
2. 每个目标区块展示识别目标所需的信息和进入详情/管理的操作；创建目标入口与列表层级清楚。
3. 覆盖无目标、多个目标及窄屏布局，并保持既有目标操作可达。

**完成条件：** 目标页以清晰分隔的区块展示目标，用户能辨认并进入各目标，空状态和创建入口明确。

## 阶段八：目标知识点选择与材料筛选

**依据：** `human-verify.record.md` 第 19 条

1. 为知识点选择页增加搜索，支持按词条查找。
2. 增加按单词词频和词族词频排序的选项，并明确当前排序方式及方向。
3. 增加来源材料多选筛选；多选时采用一致、可理解的匹配规则，并允许清除筛选。
4. 搜索、排序和筛选组合使用时保持选择状态稳定，分页或列表刷新后不丢失已选知识点。

**完成条件：** 用户可搜索知识点、按单词或词族词频排序，并同时选择多个来源材料筛选；筛选操作不会意外清除已选项。

## 阶段九：知识点库增强与详情记录

**依据：** `human-verify.record.md` 第 20 条

1. 增加知识点搜索和来源材料多选筛选，并提供按熟练度排序。
2. 在知识点库条目中展示词族信息和来源材料；来源信息应可追溯到具体材料。
3. 增加知识点详情入口，详情展示未来复习计划、学习记录及分数变化。
4. 对没有复习计划或学习记录的知识点提供空状态；分数变化应能按时间顺序理解，且数据与实际学习记录一致。

**完成条件：** 知识点库支持所需搜索、过滤和排序；每项可查看词族及来源；详情能查看未来复习计划、历史学习记录和分数变化，并正确处理无记录状态。

## 阶段十：首页答对庆祝反馈

**依据：** `human-verify.record.md` 第 21 条

1. 答题判定正确后展示覆盖全屏的庆祝动画，清晰表达答对状态。
2. 动画有明确时长和结束行为；结束后可继续当前学习流程，不阻塞后续操作。
3. 支持减少动态效果偏好，并确保动画不遮挡必要的题目反馈或操作。

**完成条件：** 答对后出现全屏庆祝反馈，反馈结束后学习流程可继续；错误答案不触发答对动画。

## 阶段十一：保存并恢复用户学习进度

**依据：** `human-verify.record.md` 第 22 条

1. 盘点当前学习进度、答题结果、复习计划及用户标识的存储方式，明确需要持久化的进度数据和恢复边界。
2. 将学习进度保存到可靠的持久化存储，并确保重新加载页面或重新进入学习时可恢复。
3. 明确进度更新与答题结算的原子性和重复提交处理，避免刷新或重试导致进度丢失、重复计数。
4. 对保存失败提供可理解的反馈与恢复策略；不得在未确认保存成功时向用户呈现为已持久化。

**完成条件：** 学习进度在页面刷新和重新进入后仍可恢复；答题结算不会因重试重复推进；保存失败有明确反馈，学习状态与计划保持一致。

## 阶段间依赖与建议顺序

- 阶段一先处理创建 API 与关联校验边界，避免后续页面调整建立在不稳定的创建契约上。
- 阶段二需要先完成 sense 释义的数据归属与缺失数据策略，再接入 ENCODE 展示。
- 阶段三和阶段四可在阶段一之后独立实施；两者均依赖对现有首页/目标详情数据刷新路径的核对。
- 阶段二与阶段三彼此独立，可按实现风险和数据迁移准备情况调整先后，但各自内部步骤不应颠倒。
- 阶段五先于阶段六；材料详情依赖分析结果和可追踪的分析状态。
- 阶段七可与阶段六并行；阶段八依赖目标知识点选择页，阶段九作用于知识点库，可独立于阶段八推进。
- 阶段十依赖答题结果反馈链路；阶段十一应先厘清持久化边界，再与答题结算、复习计划和详情记录对接。
- 阶段六、八、九的来源筛选依赖稳定的材料—知识点来源关系；若现有数据不能准确表达来源，先补齐来源数据链路。

## 后续决策检查点

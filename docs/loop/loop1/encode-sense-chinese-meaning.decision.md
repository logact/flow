# ENCODE 页面中文释义归属决策

## 背景

ENCODE 学习卡需要向学习者展示当前学习词义的中文意思。单词可能有多个 sense；如果在每次生成 ENCODE 任务时临时翻译，释义可能与当前知识点对应的义项不一致，也会在不同任务间漂移。

## 决策

- 中文释义归属于知识点所代表的具体 sense，是该 sense 的领域数据，不归属于 ENCODE 任务。
- ENCODE 展示当前 `wordId` 对应知识点/sense 的中文释义。
- 中文释义应在创建或补全知识点/sense 的流程中生成并保存；生成 ENCODE 任务时消费该值，不再把即时翻译作为释义来源。
- 任务与知识点的关联应保持明确，避免仅凭 word 文本选择释义。

## 实施方向

- 检查知识点/sense 的 domain 模型与持久化结构，增加明确的中文释义字段（字段名按现有模型约定确定）。
- 检查创建、导入或补全知识点的 application/service 流程，确定中文释义的生成与校验位置；释义需要对应 sense，而非仅对应词形。
- ENCODE 任务生成和页面展示通过关联知识点读取该释义。若任务需要历史内容稳定性，可在任务快照中复制 sense 的释义，但快照不是释义的事实来源。
- 对没有中文释义的既有知识点，需在实施时确定补齐/回填策略，并提供可理解的缺失状态；不应静默展示其他 sense 的翻译。

## 边界与待确认项

- 本决策确定数据归属与消费方向；具体由何种翻译模型/服务生成，以及既有数据如何回填，需结合当前知识点创建和存储链路进一步调查后确定。
- 英文释义、例句及其中文翻译仍属于任务内容；本决策只处理 sense 的中文释义。

## 验收标准

- ENCODE 页面显示与当前知识点/sense 对应的中文释义。
- 同一 sense 在不同 ENCODE 任务中使用一致的释义来源。
- 多义词的不同知识点可以各自保存、展示不同的中文释义。
- 缺失释义不会导致错误地借用另一义项的中文意思。

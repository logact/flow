# 目标展示页面学习进度优化计划

## 背景

目标详情页目前主要展示目标状态、R/P 流利度目标和候选知识点列表。知识点行内会显示学习状态，但缺少汇总视图，用户难以快速了解该目标的整体学习进展。

## 设计目标

在目标详情页提供清晰、可信的学习进度摘要，让用户打开目标后能快速回答：选了多少知识点、多少已经完成、R/P 当前表现如何，以及接下来可以做什么。

## 进度口径

- 统计范围为当前目标中选择“学习”的知识点。
- 一个知识点只有在 R 与 P 均已毕业时，才计为“已完成”；仅一项毕业的仍计入进行中。
- 完成率 = R、P 均毕业的知识点数 / 已选知识点数。
- 尚无已选知识点时显示空状态，不显示误导性的 0% 完成进度。
- R/P 流利度展示当前已选知识点的平均值，并与目标 R/P 值并列；没有可用学习状态时显示“待初始化”。
- 该口径衡量知识点掌握进度，不代表每日任务完成率或学习时长。

## 页面设计

在目标详情页标题和材料/操作信息下方增加进度摘要卡片：

1. **主进度**：醒目的完成百分比、横向进度条和“已完成 X / 共 Y 个知识点”。
2. **学习状态**：列出已完成、进行中、待学习数量。待学习指已选但尚未初始化学习状态的知识点。
3. **R/P 对照**：展示当前平均 R/P 与目标 R/P，使用易读数值对照；避免只用颜色表达差异。
4. **下一步提示**：有未完成项时引导“开始学习”；全部完成时提示目标已达成；无已选项时引导选择知识点。
5. **兼容状态**：加载失败沿用页面错误反馈；测评未完成或学习状态未初始化时说明原因，并避免把缺失值展示成 0。

摘要卡片需与现有页面卡片样式一致，移动端纵向排列，进度条提供可访问名称及文本百分比。更新知识点选择或学习状态后，摘要随详情数据刷新。

## 数据实现方向

- 优先由目标详情 API 返回基于该目标候选知识点计算的汇总字段，避免页面各处重复计算与口径漂移。
- 建议字段包含 `selectedCount`、`completedCount`、`inProgressCount`、`uninitializedCount`、`completionRate`、`averageFluency`（R/P）。字段须能区分“无数据”和数值 0。
- 服务端只统计 `selection === included` 的知识点；完成判定要求 `learning.graduated.R && learning.graduated.P`。
- 若短期先由客户端计算，需将统计逻辑抽成纯函数，并明确处理空集合、缺失学习状态和部分毕业情形；后续迁移至 API 时保持相同口径。

## 验收标准

- 打开目标详情页即可看到总体完成率、完成数量和 R/P 进展。
- 统计仅包含选择学习的知识点；R/P 均毕业才计为完成。
- 无已选知识点、未初始化、部分完成、全部完成等状态均有准确且可理解的呈现。
- 进度数据刷新后与知识点列表状态一致，不把每日任务完成情况误称为目标完成率。
- 桌面与窄屏布局清晰，进度条有可访问标签，关键信息不依赖颜色。

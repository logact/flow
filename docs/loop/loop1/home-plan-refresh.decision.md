# 首页手动刷新计划入口调整计划

## 背景

首页打开时会自动请求今日计划，完成任务后也会结算并刷新计划。当前“刷新计划”按钮再次调用 `GET /api/plan/today`，由服务端按当前学习状态运行今日计划刷新流程；它不承诺生成不同的任务。用户点击后若计划未变化，容易认为按钮没有响应。

## 决策建议

移除首页常驻的“刷新计划”入口。首页计划由页面加载和任务结算流程自动更新。加载失败时，在错误状态提供“重试加载”操作，文案明确表示重试，不暗示重排或更换任务。

如后续确有用户主动重排的需求，应另行定义“重新安排今日任务”的行为，包括对已有计划、已完成任务和待完成任务的影响，再决定是否提供入口。

## 实施方向

- 删除首页空状态中的常驻“刷新计划”按钮。
- 为计划加载增加明确的加载状态，避免请求期间页面看起来无响应。
- 失败时显示可理解的错误信息和“重试”按钮，重试仍调用当前计划加载流程。
- 核对首次进入首页及任务提交后的更新路径，确保移除手动入口后正常刷新行为仍完整。

## 验收标准

- 首页没有常驻的“刷新计划”按钮。
- 进入首页时自动加载今日计划；任务提交结算后按现有流程更新任务列表。
- 计划请求失败时用户能看到失败状态并可重试；请求进行中有明确反馈。
- 重试不会被描述成保证生成不同计划的操作。

## 范围说明

此文档记录待讨论/实施的产品与交互方案，不在本次文档变更中修改应用代码。是否移除按钮及后续实现以产品讨论结论为准。

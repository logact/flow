## scenarios

### scenario1：材料分析恢复与知识点排序控件

#### include decision

- `material-analysis-and-controls.decision.md`：pending 超时恢复/重试；窄屏排序控件布局和菜单锚点调整。

#### description

材料分析中断并遗留 pending 状态后，用户能够识别处理中状态并安全重试，复用已导入材料且不产生重复并发分析。知识点列表的搜索和排序控件在窄屏保持可辨认、易操作。

#### impl plan

**domain**

- 不涉及领域模型或业务规则变更。

**service**

- 明确 pending 的超时判定依据和安全重试状态转换。
- 重试时复用既有材料及分析记录，保持并发去重；保留已有失败状态处理。
- 验证处理中、超时遗留、重试成功/失败及并发请求行为。

**UI**

- 展示分析处理中状态；超过处理期限后提供清晰的恢复/重试入口及反馈。
- 调整窄屏搜索框与排序控件的尺寸和排布，必要时纵向排列；确保菜单锚定排序控件且不遮挡搜索框。

**实施记录**

- API 对仍在 2 分钟期限内的 pending 返回处理中；超时 pending 标记为失败后创建新分析，复用原材料与文本。分析页面每 5 秒刷新，超时后提供恢复/重试入口。
- 窄屏知识点搜索与排序控件设定最小可辨宽度，排序控件保持自身锚点。
- SQLite 仓储允许分析记录从 pending 转换为 analyzed/failed（同一分析 ID），并继续拒绝已结束分析记录被篡改。
- 验证：`npx tsc --noEmit` 通过。并发去重仍由 API 进程内材料锁保证。

### scenario2：学习续接与答题交互

#### include decision

- `learning-feed-and-task-interaction.decision.md`：续接未完成任务；答错时显示 feedback；避免目标词泄露；打乱选项并保持 ID 绑定；提交等待状态。

#### description

返回首页后继续当日首个未完成任务；答题流程提供明确、准确的反馈。判错显示对应题目 feedback，判对不显示纠错文本。回忆题不泄露目标词，选择题选项随机呈现但判题仍按 option ID，提交期间防止重复操作并显示处理中状态。

#### impl plan

**domain**

- 选项顺序变化时正确答案继续由稳定的 option ID 标识，领域判题不依赖选项位置。
- 检查现有任务/判题结构能否表达题目是否需要回忆目标词，以及呈现顺序的持久化或稳定性要求；按已有决策保持判题语义不变。

**service**

- 生成或校验回忆题题干与提示，不得直接包含目标词。
- 保持判题 feedback 原样传递，并提供足够的判定结果让 UI 区分正误。
- 确认首页数据可定位当日最近完成任务之后的首个未完成任务；无未完成任务时保留完成态。

**UI**

- 首页加载时恢复到当日首个未完成任务；全部完成时显示今日完成状态。
- 仅答错时展示当前题目的判题 feedback；答对时不展示纠错文本。
- 选择题选项呈现前打乱顺序，保留 ID 与正确答案绑定。
- 提交后等待判题时显示明确动画/状态，并禁用重复提交；判题完成后恢复正常交互。

**实施记录**

- 首页计划加载后自动滚动至当日首个未完成任务；今日任务全部完成时不改变完成态。
- 判错时才展示当前题 feedback；需要回忆目标词的 P 题校验题干/提示不泄露目标词；RETRIEVE 与 FLUENCY 阅读选择题均按 Fisher–Yates 打乱显示顺序但仍提交原 option ID；提交期间显示旋转状态并禁用重复提交。
- 验证：`npx tsc --noEmit` 通过；领域、任务生成、知识点选择与结算测试共 109 项通过。

### scenario3：学习记录与毕业时更新词频估计

#### include decision

- `learning-history-and-vocabulary-estimate.decision.md`：完成任务学习记录及分数证据；词频估计仅在知识点毕业时更新一次。

#### description

知识点详情展示所有已完成的 ENCODE/RETRIEVE 等学习事件。只有存在已结算 attempt 时展示真实流利度变化。作答结算更新 R/P 流利度，但不直接影响词频掌握度；知识点达到毕业条件时，若存在匹配当前词表版本的分类，则将该知识点作为一次已掌握样本计入对应词频段。重复触发毕业、重修或重复结算不得重复计数。

#### impl plan

**domain**

- 从 `settleTaskAttempt` 中移除按每次作答更新词频估计的行为，同时保留结算时 R/P 流利度更新。
- 在知识点毕业状态转换处更新词频估计：匹配当前词表 ID、版本及词频段后，样本数与认识数各增加一次并重算掌握概率及区间。
- 通过持久化的毕业/计入标记或等效幂等机制，确保同一知识点最多计入一次；重复事件不重复累加。
- 分类缺失或词表版本不匹配时不推断词频段；遵循现有领域校验规则。

**service**

- 将毕业状态转换与词汇估计更新放在可一致提交的应用流程中，确保失败重试不会漏计或重复计数。
- 知识点详情查询合并已完成任务与已结算 attempt；无结算证据的任务只产生学习事件，不虚构分数变化。
- 保持现有词表分类加载与版本匹配约束。

**实施记录**

- 普通作答结算仍更新流利度，但词频估计保持不变；R/P 均毕业时，在结算同一事务中计入一个已掌握样本，并写入幂等标记。
- 知识点详情 API 与页面合并已完成任务和结算 attempt；无结算证据的完成事件单独标识，分数变化只从结算记录生成。
- 验证：结算测试覆盖毕业计数及重复结算不重复累加；知识点历史测试覆盖无结算记录的已完成任务展示。

**UI**

- 学习记录展示已完成任务事件；对已有结算证据展示实际 R/P 分数变化，对无证据事件不显示虚构变化。
- 区分“有学习事件但没有分数变化记录”与“没有学习记录”的状态。
- 若产品已有毕业状态展示，确保毕业后词汇估计更新的结果可在词汇估计页面查看；不额外引入未经决策的毕业交互。

### scenario4：ENCODE 发音与音标

#### include decision

- `encode-pronunciation.decision.md`：播放目标词发音并显示可获得音标，缺失时明确提示。

#### description

材料分析完成词义消歧并确定知识点 lemma/词性后，通过免费的 Free Dictionary API（dictionaryapi.dev）查询音标与音频地址，并将匹配结果缓存为词条级元数据。生成 ENCODE 任务时从知识点快照附上缓存值，用户点击时播放缓存的音频 URL，不在任务生成或播放时实时查词典。无匹配结果或外部 API 不可用不阻塞材料分析和学习，页面显示“音标暂缺”并允许之后重试。保留来源标识/链接；不下载或重新分发音频，发布前复核署名和使用许可。

#### impl plan

**domain**

- 为词条表达可选 IPA、音频 URL、来源和查询时间；缺失元数据是允许状态。

**service**

- 在知识点解析完成后查询 `GET https://api.dictionaryapi.dev/api/v2/entries/en/{lemma}`，核验 lemma，并在词条响应能明确关联词性时再选择 `phonetics` 发音项；缓存 IPA、音频 URL、dictionaryapi.dev 来源标识及查询链接。无法可靠关联时保持缺失，不猜测。
- 外部查询失败、无匹配项或响应异常时不阻断材料分析/任务生成，保留缺失状态并支持后续重试；不在每次生成任务或点击播放时重复查询。
- 不生成未经核验的音标；免费公共 API 无明确 SLA，上线前复核数据/音频许可与署名要求。

**UI**

- 将原型提示按钮改为播放已缓存的音频 URL，展示 IPA 或“音标暂缺”。
- 在播放中、播放结束和播放失败时提供清晰状态反馈，并展示发音数据来源；缺少音频时禁用播放，不以浏览器合成语音替代词典发音。

**实施记录**

- 知识点增加可空词条级 IPA、音频 URL、来源、查询链接与查询时间。材料分析确定 lemma/词性后请求 Free Dictionary API，按返回词条与词性核验；调用失败或无匹配时留空，不阻断分析。
- ENCODE 任务从知识点快照复制缓存值；页面播放缓存 URL，展示音标缺失、播放状态及来源链接。知识点详情提供重新查询入口。
- 验证：`npx tsc --noEmit` 通过；全量 Jest 26 个 suite、275 项通过。
- 发布前事项：复核 Free Dictionary API 音频/数据许可及署名要求；当前实现保留来源，不下载或重新分发音频。

### scenario5：初始词汇流利度规则

#### include decision

- `initial-vocabulary-fluency.decision.md`：以词频段掌握概率初始化 R/P 流利度，阈值 0.7。

#### description

新知识点初始化及新词准入预测采用一致规则：匹配词频段掌握概率低于 0.7 时 R/P 均为 0；达到或超过 0.7 时 R=40、P=20。缺少可用词汇估计、匹配分类或对应词频段时按 0 处理，分类词表版本不匹配时遵循领域校验拒绝混用。

#### impl plan

**domain**

- 更新初始流利度推导规则，确保阈值边界和输出值符合 decision。
- 确认正式初始化与新词准入预测共用同一推导规则，避免行为分叉。
- 保持词表 ID/版本一致性校验。

**service**

- 继续加载当前词汇估计及匹配分类并传入领域推导；不新增额外服务规则。

**UI**

- 不涉及；继续展示初始化后的 R/P 值。

**实施记录**

- 领域推导统一改为：低于 0.7 时 R/P=0；达到或超过 0.7 时 R=40、P=20。正式初始化与准入预测沿用同一 `deriveInitialFluency`。
- 验证：边界测试覆盖 0.699、0.7、1.0 与无分类；知识点初始化测试同步更新，新规则相关测试通过。

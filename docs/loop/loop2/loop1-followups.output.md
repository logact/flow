## 词汇测评抽样算法优化

### 需求与现状

优化词汇测评的抽样算法，并将抽样策略放在 domain 层定义和实现；本 loop 仅承接讨论事项，不代表已确认或实施方案。

- domain 函数 `sampleVocabularyForAssessment` 位于 `lib/domain/functions.ts`。
- 目前按词频段分层；每层根据调用方传入的 `sampleCounts` 抽样。
- 每层按词族 ID 排序后，使用 seed 驱动 Fisher–Yates 洗牌，再取前 N 个。因此给定相同词表、配置和 seed 时结果可复现，层内为不放回抽样。
- 默认配置由 `app/api/assessments/route.ts` 提供：1k–20k 每段抽 5 个，共 100 个词族。
- 当前估计以每个词频段的“认识数 / 样本数”作为掌握概率，并计算 Wilson 区间。
- 现有抽样不读取历史测评记录，因此重测时没有避免重复出题的机制；每层固定样本数也没有按词族总体规模或估计不确定性调整。

### 待讨论

1. 是否按词频段总体规模分配样本数，还是继续每段固定数量；总题数与测评时长如何权衡。
2. 是否让后续测评参考历史结果，优先抽取未测词族或不确定性较高的词段；如何定义重复率及历史数据输入。
3. 分层概率估计是否继续使用简单样本比例，或需要纳入总体规模的加权估计及相应区间。
4. 随机种子、可复现性、词族去重、词段样本不足等规则应由 domain 负责并如何验证。
5. domain API、application 输入及 API 默认配置需要如何调整，并明确迁移与兼容方式。

**状态：**仅承接调查结果和待讨论问题；需确认抽样目标、约束和验收标准后再制定实施计划。

## 错题答案与原因反馈

### 需求与背景

学习者答错题目后，应看到该题的正确答案，以及解释为什么答错或正确答案为何成立，帮助学习者理解并纠正错误。当前任务内容中已有部分正确答案和解释，但提交结果及页面反馈未必能将其按题目返回和展示。实现可能涉及 domain、application service、API 响应及学习页面组件。

### 待讨论

- 哪些题型纳入范围：主动提取选择题、提示/自由作答题、阅读理解选择题与自由题等。
- “解释为什么错”的含义与来源：现有答案解释是否足够；自由作答是否需要针对用户答案生成具体纠错理由。
- 反馈展示时机与形态：逐题或整题展示、部分正确处理、答案和解释的呈现方式。
- 答案及反馈的持久化与 API 边界：确保答题前不泄露答案，并让首次提交、重试和历史结果一致。
- 兼容 AI 判题与规则判题，以及缺少参考答案/解释时的处理方式。
- 明确 domain/service/API/UI 修改范围和验收标准。

**状态：**仅承接需求，尚未确认实现细节；需先讨论并形成决策，再制定实施计划。

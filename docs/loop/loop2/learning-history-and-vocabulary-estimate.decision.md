# 学习记录展示与词汇估计更新决策

## 决策

- 对应人工评审第 11 条：知识点详情中的学习记录应覆盖该知识点已完成的 ENCODE/RETRIEVE 等任务；分数变化按已结算 attempt 的流利度变化记录呈现。任务已完成但没有可用结算记录时仍显示学习事件，不虚构分数变化。
- 对应人工评审第 12 条：答题结算时更新 R/P 流利度，但不立即更新词频掌握度估计。只有知识点达到毕业条件时，才将其作为已掌握样本计入与当前词汇表版本匹配的词频段，更新该段样本数、认识数和掌握概率。毕业计入必须幂等，同一知识点不得因重复结算、重修或重复触发毕业而重复计数。未毕业的答题结果不改变词频估计；缺少匹配分类时不推断词频段变化。

## 调查依据

- 知识点详情 API 目前仅从 `attempts` 生成学习记录，因此完成任务若没有匹配的 attempt 将完全不可见；流利度变化也只从已结算 attempt 读取。
- 当前实现中，`settleTaskAttempt` 会更新相应 R/P 流利度，并调用 `updateVocabularyEstimate`：匹配当前词表分类时，每次结算都会累计样本，答对增加认识数，答错只增加样本数。此行为是待调整的现状；本决策改为仅在知识点毕业时计入一次已掌握样本。

## 实施范围

- **Domain**：将词频估计更新从每次作答结算移至知识点毕业事件；毕业样本仅计入一次。流利度仍在作答结算时按 R/P 规则更新。
- **Service**：详情查询合并完成任务和结算记录，避免把缺少分数变化误表示为没有学习。
- **UI**：显示真实学习事件；仅对已有结算证据显示分数变化，空状态分别表达。

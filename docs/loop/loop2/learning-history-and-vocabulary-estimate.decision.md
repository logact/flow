# 学习记录展示与词汇估计更新决策

## 决策

- 对应人工评审第 11 条：知识点详情中的学习记录应覆盖该知识点已完成的 ENCODE/RETRIEVE 等任务；分数变化按已结算 attempt 的流利度变化记录呈现。任务已完成但没有可用结算记录时仍显示学习事件，不虚构分数变化。
- 对应人工评审第 12 条：有效作答判题并结算后会影响学习者词汇水平估计。若知识点有与当前词汇表版本匹配的词频分类，系统用该次判题结果更新对应词频段的样本数、认识数和掌握概率；流利度分数另按 R/P 规则更新。无匹配分类时只更新流利度，不推断词汇段变化。仅提交但未结算的作答不更新两类分数。

## 调查依据

- 知识点详情 API 目前仅从 `attempts` 生成学习记录，因此完成任务若没有匹配的 attempt 将完全不可见；流利度变化也只从已结算 attempt 读取。
- `settleTaskAttempt` 会更新相应 R/P 流利度，并调用 `updateVocabularyEstimate`。后者只在匹配当前词汇表版本的分类和词频段时累计样本；答对增加认识数，答错只增加样本数并重算掌握概率。

## 实施范围

- **Domain**：保持当前结算时更新流利度与可用词汇估计的规则。
- **Service**：详情查询合并完成任务和结算记录，避免把缺少分数变化误表示为没有学习。
- **UI**：显示真实学习事件；仅对已有结算证据显示分数变化，空状态分别表达。
